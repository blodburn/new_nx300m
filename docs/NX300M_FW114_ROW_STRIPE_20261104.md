# NX300M FW1.14 — freestanding copy-owned row-strip renderer (offline)

Status: **host/QEMU synthetic API only; physical camera firmware and flash remain NO-GO.**

## Independent processing path

```text
Caller-owned, independent, complete copied Y plane + 4:2:0 C plane
       | full-frame dimensions, strides, byte lengths
       v
Explicit BT.601 FULL CbCr/CrCb HYPOTHESIS (not camera proof)
       | global input y = first_row + local_row
       v
sRGB decode table (256) -> RGB12 LUT2/18/65
       | sRGB encode table (4096)
       v
Caller-owned local RGB888 STRIPE [row_count x width x 3]
       | callback/JPEG handoff is NOT implemented
       v
Host can consume rows in order; no camera ISP/EXIF/JPEG API call
```

## API

`nx_film_core_render_owned420_rows_hypothesis(job, first_row, row_count)`

- Preserve the original `nx_film_owned420_hypothesis_job` struct ABI and the original full-frame `nx_film_core_render_owned420_hypothesis(job)` export.
- `job->height`, `job->y`, `job->chroma`, and their length/stride fields cover the **full** independent input copy.
- `job->rgb` starts at the **first output row of this stripe**, not offset by `first_row * rgb_stride`. The minimum output byte length is `(row_count-1)*rgb_stride + width*3`. Row padding must not change.
- `first_row` may be even or odd; global row indexing determines chroma line `row/2`. A final partial stripe is supported.
- All bounds, dimensions, lengths, table counts and output overlaps with source/LUT/gamma/job memory are rejected **before output writes**. Failure returns -1; success returns 0.
- The caller retains ownership of input and output. The DSO does not allocate, lock, access device memory, open files, invoke JPEG encoders, or retain pointers.

For a hypothetical 5546 × 3714 20.6 MP frame, full RGB888 staging needs 61,793,532 bytes (~58.9 MiB), while **one packed RGB row** needs 16,638 bytes. This is an output staging comparison **only**: full copied Y/C planes, LUT nodes, gamma tables, other host/camera memory and target performance are **not** included. There is no measured camera RAM saving.

## Host/QEMU acceptance gates

- Compare full-frame RGB output against an independent host oracle for 2³, 18³ and 65³ LUTs, both synthetic chroma order hypotheses.
- Emit one-row stripes and mixed three-row/partial stripes; require bit-identical RGB including untouched padding.
- Reject invalid row count, overflow/end-row, too-short output, overlapping source/output, invalid height/format/gamma metadata. Validate immutability.
- Build a freestanding ARMv7/VFPv2 EABI5 shared library; enforce no external shared libraries, GLIBC versions or unresolved named globals, and exactly three explicit exports.

These tests do **not** establish actual NX300M 1.14 Y/C420 color order, ISP buffer ownership, DMA coherency, Tizen module loader compatibility, safe JPEG callback insertion, EXIF/MakerNotes preservation, RAW+JPEG behavior or full-brick recovery. **Never flash or deploy this offline test artifact to camera.**
